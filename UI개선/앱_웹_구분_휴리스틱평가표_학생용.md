# **휴리스틱 평가표**

APP · WEB 구분 | UI 개선 프로젝트 학생용

### **평가의 목적**

"예쁘다/불편하다" 수준의 감상에서 벗어나, UI 이론과 Nielsen의 10가지 휴리스틱을 근거로 문제를 진단하고 사용자 영향과 개선 방향까지 연결한다.

### **사용 순서**

- ① 핵심 Task를 정한다 → ② 화면을 실제로 사용한다 → ③ 문제를 화면 캡처와 함께 기록한다 → ④ 관련 휴리스틱과 UI 이론을 연결한다 → ⑤ 심각도를 결정한다 → ⑥ 개선 우선순위를 정한다.

### **심각도 0–4**

- 0 문제 없음 · 1 미관상/경미 · 2 작은 사용성 문제 · 3 주요 문제(개선 필요) · 4 치명적 문제(Task 수행을 막음).

기반: Nielsen Norman Group의 10 Usability Heuristics를 앱/웹 수업 맥락에 맞게 재구성

## **APP vs WEB | 평가 시 관점 차이**

동일한 휴리스틱을 사용하되 플랫폼별 사용 환경과 상호작용 관습을 구분합니다.

|**평가 관점**|**APP에서 더 중요하게 볼 것**|**WEB에서 더 중요하게 볼 것**|
|---|---|---|
|**조작**|터치 타깃, 한 손 사용, 제스처, 하단 내비게이션|마우스+키보드, Hover, Focus, 링크/버튼 구분|
|**이동**|뒤로가기, 탭 구조, 화면 전환, OS 관습|브라우저 Back/Forward, URL, Breadcrumb, 새 창|
|**상태**|권한, 네트워크, 로딩, 앱 생명주기 상태|페이지 로딩, 검색/필터, 폼 제출, 세션 상태|
|**레이아웃**|작은 화면, Safe Area, 키보드 노출, 세로 흐름|반응형, 다양한 뷰포트, 긴 페이지, 다단 레이아웃|
